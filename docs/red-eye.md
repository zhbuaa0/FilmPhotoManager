# 本机去红眼

1.12.0 加入本机去红眼。照片不上传，原始扫描文件保持只读。自动检测是保守的辅助工具；小脸、眼镜反光、颗粒和偏色可能漏检，导出前请检查眼部对照。

## 使用

打开照片，点击「一键去红眼」；也可在胶卷详情勾选照片后点「选中去红眼」，或点「整卷去红眼」。处理采用当前成片 / 扫描原片偏好；放大窗口单张处理使用正在查看的具体版本。

结果中，可靠候选默认启用，疑似候选保持关闭。像素不足的情况单独显示「眼部无法判断」，不作为疑似红眼候选。每只眼睛都有原图 / 修正后放大对照，可以勾选、调整强度和范围、删除选区。漏检时打开「手动点选」，点击原图的红色瞳孔；可放大至 2 倍 / 4 倍，并调整搜索范围。没有识别人脸时也允许手动补选。重复点击同一个瞳孔替换选区，不叠加修正。

「显示修正版」控制接触印样、胶片条和新生成的整卷预览；照片放大窗口另有修正版开关。「复制原图」和「下载原图」始终提供原文件。修正版以原分辨率、无损 Deflate TIFF 导出，Windows 还支持多选「复制修正版」，然后在文件资源管理器粘贴。所选版本必须都有有效修正，否则停止整批复制并提示。

「撤销这批修正」恢复这批自动检测前的记录，跳过之后手动修改过的照片。「撤销本张修正」先恢复本轮手动修改前的选区；再次点击可移除检测记录。重新检测可通过整批撤销恢复先前记录。撤销不删除源照片，已经导出或粘贴的文件不会随撤销改变。

任务在 Node 服务后台执行；关闭弹窗或浏览器后继续，停止服务则暂停执行，下次启动自动恢复未完成任务。「取消剩余任务」保留已完成结果；当前正在计算的一张完成后丢弃结果，再停止剩余项。

## 1.13.0 判定更新

红眼判定改为结合局部颜色对比、瞳孔与周围的亮度、形状及双眼位置关系。用于形状分析时闭合单像素颗粒间隙、填补高光空洞，允许偏粉的闪光点；不会因棕红色不够鲜红而直接卡住旧版的绝对颜色门槛。中央黑瞳孔、无眼部结构的皮肤色块、过小的彩色反光和远离眼睛定位点的单眼候选受到单独限制。单眼可以独立确认；双眼一致性只增强各自已经通过基础瞳孔检查的候选，不会把缺失或弱色块一起提升。

新增的棕红自动确认通道还要求足够的瞳孔像素、红色轮廓包围的内部高光，以及局部对比；双眼一致性不能把眼角的亮色皮肤一起提升。原有强红眼证据也继续接受瞳孔形状、黑色中心等检查。

这些分数是规则评分，不是经过标注集校准的概率。仍可能漏检或误判，尤其是小脸、眼镜和彩色反光；导出前请核对。

已有修正记录与手动选区保留。旧记录会提示「检测规则已更新」，点击「重新检测」才使用新规则；重新检测可撤销。历史 HTML 测试报告是快照，应查看新报告获取新结果。

## 1.13.1 修正更新

修正阶段改用局部瞳孔蒙版。旧版直接在整个选区椭圆内中和偏红像素，可能同时压灰正常棕色虹膜；椭圆的固定羽化也可能削弱已确认瞳孔边缘的修正，留下红环。新版在已有选区内选择靠近中心的红色连通区域，只向相邻像素平滑过渡，保留外围虹膜和独立色块。选区椭圆继续作为不得越过的边界，手动强度与范围仍生效。

蒙版会闭合颗粒造成的细小裂隙，并填充红色轮廓包围的高光空洞，较大的粉色、黄色闪光点也纳入处理。中性白色高光不改动；稀释高光在中和颜色时保留近似像素亮度，避免随瞳孔一起压暗。普通瞳孔像素继续用绿色和蓝色分量中和红色，保留原来的细微纹理。没有生成新眼睛，也无法恢复闪光已掩盖的真实虹膜信息。检测选区正确不等于修正自然，应分别查看修正前后对照。

渲染版本更新为 `pupil-mask-v3`，服务器缓存、眼部对照、缩略图和放大预览都包含此版本。刷新页面即可用现有选区重新生成修正版，无须重新检测或覆盖手动记录；已导出的旧 TIFF 不会自动改变。

本轮复用了同一实际照片集中的 49 组已启用选区、84 个眼区（覆盖当时保存的修正记录），逐眼查看原图、旧修正和新修正。49 份原尺寸 TIFF 均通过尺寸、位深、ICC、方向、选区外像素、中性高光和像素映射检查。新增合成回归同时检查棕色虹膜、独立色块、粉黄高光空洞、暗纹、边缘残红、强度和 8-bit / 16-bit；全套 52 项测试通过。这是渲染回归，没有重新检测全库或重新评估召回率。

## 1.13.2 网页整图预览

去红眼弹窗的大图原本固定显示原图，仅眼部对照和 TIFF 导出应用修正，容易被误认为网页修正没有生效。现在默认显示「修正后」，可通过「大图显示」切换原图对照；修正后不叠加选区边框，便于判断实际效果。未检测的照片显示原图并提示。

开启「手动点选」时临时切回原图，并暂停大图显示切换；退出后恢复此前选择的预览。快速切换时只接受最新加载结果，载入失败会清空旧画面，避免把旧预览误当作当前效果。本次只修正显示逻辑，不改变检测算法、像素修正、导出文件或已有选区。

## 实现与数据

- `red-eye-detector.mjs`：离线 YuNet 人脸 / 眼睛定位，sRGB 检测代理采用全图及重叠分块；规范坐标以 EXIF 归正后的图像为基准，显示旋转在点选时反变换。
- `red-eye-mask.mjs`：独立实现局部红色优势、连通区域、形状和位置判断。不处理宠物黄眼 / 绿眼。
- `red-eye-pupil-render.mjs`：在选区内分割确认的红瞳孔，用距离场平滑边缘、保护虹膜和高光；8-bit / 16-bit 使用相同处理尺度。
- `red-eye-render.mjs`：从源版本重新读取 8-bit / 16-bit RGB 像素；母版保留位深、ICC 和密度，应用显示旋转后写入 Orientation=1。无 ICC 的 RGB 按 sRGB 解释；CMYK 请先转 RGB。不会把整份源 EXIF / IPTC / XMP 复制到新 TIFF，原文件保留这些信息。
- `tiff-profile.mjs`：仅给自己生成的单页标准 TIFF 附加源 ICC，不执行二次全图色彩转换。RGB、未旋转母版的选区及羽化区域外像素保持一致；JPEG 浏览预览经过 sRGB 转换、缩放和重编码，不承诺逐像素相同。
- `red-eye-service.mjs` / `red-eye-worker.mjs`：独立 Worker，图像任务串行执行，CPU 推理，单项超时 180 秒。单图上限 8000 万像素；超大扫描仍可能需要较多内存。模型加载失败或单张源文件离线会显示错误并继续其他项。

每张照片的 `redEye[versionId]` 保存在 `data/library.json`，绑定源文件 SHA-256、尺寸、方向坐标系、修订号、选区与强度。处理前后校验文件，源发生变化时要求重新检测。浏览缓存同时绑定版本、修订号、旋转角度和输出规格。

`data/red-eye/jobs.json` 保存最近 80 批任务及撤销快照；`data/red-eye/renders/` 是可重建缓存，`data/clipboard/` 保存供 Windows 粘贴的文件。备份修正记录需要备份整个 data；引用导入还需保留原目录。缓存和已导出文件暂不自动清理。

## 模型与来源

YuNet 2026may 动态输入模型来自 [OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)，随仓库分发；下载地址、大小与 SHA-256 记录在 [manifest](../models/red-eye/manifest.json)，运行时核对哈希。其 MIT 许可证保存在 [LICENSE](../models/red-eye/LICENSE)。推理依赖固定为 `onnxruntime-node@1.31.1`，见 [官方 Node 平台支持](https://onnxruntime.ai/docs/get-started/with-javascript/node.html)。安装依赖需要联网，安装完成后的检测与修正不访问外部接口。

项目 `.npmrc` 将 `onnxruntime-node-install` 设为 `skip`，仅跳过额外的 CUDA / TensorRT 下载；CPU 原生绑定仍由 npm 包提供并接受真实模型测试。请保留这个配置，避免 Linux 默认安装流程尝试下载本应用不使用的 GPU 库。

交互参考 [GIMP 去红眼](https://docs.gimp.org/3.0/en/gimp-filter-red-eye-removal.html) 的局部选择 / 阈值思路，以及成熟照片管理软件的批量检测、人工核对流程。颜色分割及修正代码自行实现，未移植 GPL 滤镜源码。

## 验证范围

自动检查覆盖局部修正、选区外像素、高光、四向坐标、EXIF 归正、8-bit / 16-bit TIFF、P3 ICC、BMP、源哈希、照片版本隔离、重复补选、HTTP 导出、取消、撤销及重启恢复。另在 Windows 实测自动候选、手动补选、眼部对照和文件剪贴板。

1.12.1 另在本地抽样 107 张真实胶片照片，覆盖 JPEG / BMP / TIFF；检测自动启用 4 只眼睛，经人工查看均为红眼。37 张保留待核对，30 张未识别人脸，这些结果不能当作无红眼。抽样暴露了只降低红通道导致瞳孔偏绿的问题，现已改为在局部蒙版内中和 RGB，并增加 8-bit / 16-bit 回归用例及渲染版本缓存失效。私人照片和逐张报告不进入仓库。

1.13.0 在同一本地照片集进行修复回归：36 卷、1208 帧、1456 个档案版本，包含副本共 2641 个图片文件，按完整内容、解码方式和显示旋转分为 1461 个检测组合。默认优先成片口径下，自动生成修正从 7 张增至 26 张，待核对从 313 张降至 156 张，另有 11 张单独列为「眼部无法判断」。减少的待核对包含无关色块过滤及可靠候选自动确认，不代表全部被判为没有红眼。

本轮 84 个自动眼区均查看了原图与修正后对照，未发现需要阻止发布的误选；原有人工查看过的 23 个自动眼区继续保留。94 份原尺寸 TIFF 导出通过尺寸、位深、ICC、方向、选区外像素及中性高光检查。实际照片均解码为 8-bit；16-bit 仍由合成回归用例验证。照片、逐张报告、原图路径及修改记录仅保留在本机。

这些是功能回归与自动结果的视觉检查，未建立完整逐眼真值标注，不能据此计算整体精度、召回率或宣称全自动可靠；真实红眼仍可能漏检或只被列为待核对。
